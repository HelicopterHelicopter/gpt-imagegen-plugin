# Node Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Go implementation with a Node one that ships as a single committed bundle, eliminating per-platform binaries, the release pipeline and the installer script.

**Architecture:** Same design, same spec, new runtime. `puppeteer-core` drives the user's existing Chrome (never a downloaded browser). The entry point stays a CLI whose stdout is exactly one line of JSON. esbuild bundles everything to `dist/index.cjs`, which IS committed — that single fact is the entire reason for this port.

**Tech Stack:** Node 20+, `puppeteer-core`, `esbuild` (dev only), `node:test` + `node:assert` (no test framework dependency).

**Spec:** `docs/superpowers/specs/2026-09-01-gpt-imagegen-design.md` — unchanged and still binding. Sections 3, 6 and 7 are load-bearing.

**Port source:** the Go implementation on this branch. Every task names the Go file it ports. **Read that file.** It is correct, reviewed, mutation-tested and verified end-to-end against real ChatGPT — it is the specification for its own port, and its comments record why each non-obvious thing is the way it is.

## Global Constraints

These are not style preferences. Each one was learned by something breaking.

- **Never delete the profile directory.** In Go this meant never calling `launcher.Cleanup()`, which does `os.RemoveAll(UserDataDir)` and once destroyed a real ChatGPT login. In puppeteer the equivalent hazards are letting it manage a temp `userDataDir`, or passing our profile path somewhere that gets cleaned. Our profile at `~/.gpt-imagegen/profile` must survive every run and every crash.
- **Never log values from `/api/auth/session`.** It carries `accessToken` and `sessionToken`. Log sorted key names only.
- **Never headless.** It is the strongest bot-detection signal. The flag exists for tests only.
- **puppeteer adds `--enable-automation` by default — remove it** via `ignoreDefaultArgs`. Also keep `--disable-blink-features=AutomationControlled`, `--no-first-run`, `--no-default-browser-check`. These flags are why ChatGPT does not challenge us.
- **Only close a browser we launched.** Attach and launch are different lifecycles.
- **Close gracefully** so cookies flush to disk; a hard kill can silently log the user out.
- **stdout is exactly one line of JSON.** All human output to stderr. The skill parses stdout unconditionally and branches on `error.code`, never on prose.
- **No retry loops anywhere**, in code or in SKILL.md.
- **Archive only on success**, never on a failure or salvaged-timeout path — a failed run's `conversation_url` is the user's only recovery.
- Generated images: host must be OpenAI-owned (`chatgpt.com`, `*.chatgpt.com`, `chat.openai.com`, `*.oaiusercontent.com`), path exactly `/backend-api/estuary/content`, `id` prefixed `file_`. Match on that, never on response size — size heuristics captured sprite sheets and avatars.
- DOM identifier for a generated image is the alt prefix `Generated image: ` (trailing space).
- Node 20+ (for stable `node:test`). Declare it in `engines`.

**Security note:** `isGeneratedImageUrl` is a security boundary, not a convenience filter. It guards the in-page fetch, whose URLs come from page DOM and are forgeable by prompt injection. Use `new URL(u)` and compare `url.hostname` (not `host`, which carries the port), lowercased. The Go tests encode the attacks that must stay rejected — port every case:

- `https://attacker.example.com/backend-api/estuary/content?id=file_x` → false
- `https://chatgpt.com.evil.com/...` → false (suffix confusion)
- `https://evilchatgpt.com/...` → false
- `https://chatgpt.com@attacker.example.com/...` → false (userinfo bypass; verify what `new URL().hostname` returns here and assert it)
- `https://chatgpt.com/evil/backend-api/estuary/content?id=file_x` → false (path must be exact)
- `https://chatgpt.com/backend-api/estuary/content?id=notaprefix` → false
- `https://chatgpt.com:443/...?id=file_x` → true
- `https://cdn.oaiusercontent.com/...?id=file_x` → true
- The real spike URL → true
- Real UI-chrome URLs (`cdn/assets/sprites-shell-*.svg`, `watercolor-*.webp`, a `googleusercontent.com` avatar, `cdn.auth0.com/avatars/*`) → all false

`isGeneratedImageUrl` and `fileIdFromUrl` must AGREE on every input. Assert that.

### Task 5: The cross-process lock

**Files:**
- Create: `src/lock.js`, `src/profile.js`
- Test: `test/lock.test.js`

**Port source:** `internal/session/profile.go`.

**This is the one place the port genuinely regresses.** Go used `syscall.Flock`: kernel-enforced, released automatically on process death, immune to staleness. **Node has no `flock`** (`fs.flock` is undefined) and adding a native addon would break single-file bundling, which is the entire point of this port.

So implement a PID-file lock — the scheme Go started with — but written correctly from the start. Review found exactly three bugs in that scheme; all three are avoidable now that we know them:

1. **EPERM means the process is ALIVE, not dead.** `process.kill(pid, 0)` throws `EPERM` when the pid belongs to another user's live process. Treating that as dead steals a live lock. Only `ESRCH` means gone.
2. **Release must check ownership.** Removing the file unconditionally can delete a different run's live lock. Re-read it and only remove if it still holds our own pid + nonce.
3. **Stale reclaim must not be blind-remove-then-retry.** That is a TOCTOU where two processes both win. Write a unique nonce with the pid, and when reclaiming, only remove the file if its contents still match what you inspected.

Use `fs.openSync(path, 'wx')` for the atomic create. Check the deadline on **every** iteration, not only before sleeping — Go skipped it on one path.

**Tests, including the one that matters most:**
- Second acquire returns a `PROFILE_LOCKED`-shaped error after roughly its timeout, not instantly.
- Release then re-acquire succeeds; release is idempotent and safe on a null lock.
- A lock owned by a **dead** process is reclaimable. Test this for REAL with a child process: spawn `node -e` that acquires and sleeps, confirm the parent is blocked, `SIGKILL` the child, confirm the parent then acquires. Go's equivalent test was skipped once as "unreliable"; it was made real with a self-exec pattern and then mutation-proven. Do the same here — and **prove it fails** if you remove the staleness check.
- A lock whose file contains a live pid owned by another user is NOT stolen (simulate by writing pid 1, which is root-owned and alive; `process.kill(1, 0)` should throw EPERM).

- [ ] Port/write tests → fail → implement → green → mutation-check → commit.

### Task 6: Browser session lifecycle

**Files:**
- Create: `src/session.js`, `src/window.js`
- Test: `test/session.test.js`

**Port source:** `internal/session/browser.go`, `devtools.go`, `auth.go`, `window_darwin.go`.

**Interfaces:**
- Produces: `chromePath()`, `endpointFromProfile(dir)`, `parseDevToolsActivePort(raw)`, `open({headless, hideWindow})`, `close(browser)`, `auth(browser)`, `parseAuthBody(body)`, `hideWindow(pid)`.

Carry over exactly:
- **Attach-or-launch.** Read `DevToolsActivePort` from the profile dir (two lines: port, ws path), verify liveness with `GET /json/version`, and connect. `puppeteer.connect({browserURL: 'http://127.0.0.1:<port>'})` does this natively — simpler than the Go path. - **`hideWindow` is an explicit per-call argument, never inferred from `headless`.** Inferring it hid the sign-in window, which was a blocker found only by whole-branch review. `setup` and `doctor` pass false; `generate`, `edit`, `probe` pass true.

- **Auth probe in its own throwaway page**, closed on every path, so a page mid-login is never navigated. Parse with `parseAuthBody`; treat a `user` value as logged in only when it is a non-empty object (`{"user": false}` and `{"user": ""}` must not count). Return sorted key names only — never values.
- **`chromePath`**: `$GPT_IMAGEGEN_CHROME`, then per-platform well-known paths, then `PATH` lookup. Port the Go version's list.

**Tests** must not require a real Chrome or a login: env override wins; a set-but-missing override errors; `parseDevToolsActivePort` handles malformed input; a dead port is rejected (use a closed local port); `parseAuthBody` never leaks values (assert against a payload containing distinctive sentinel token strings); an attached browser is never closed.

### Task 7: Image capture

**Files:**
- Create: `src/capture.js`
- Test: `test/capture.test.js`

**Port source:** `internal/capture/capture.go`.

**Interfaces:**
- Produces: `createRecorder(page)`, `recorder.start()`, `recorder.files()`, `recorder.mime(id)`, `recorder.url(id)`, `recorder.ids()`, `recordFinished(rec, entry, fetchBody)`, `fetchInPage(page, url)`, `decode(body, isBase64)`, `dimensions(buf)`.

Simpler in puppeteer: `page.on('response')` plus `response.buffer()` replaces the hand-wired CDP event pair.

Keep these, each from a review finding:
- **Record url and mime even when the body fetch FAILS.** That failure is the buffer-eviction case the in-page fetch fallback exists for; dropping the metadata meant a webp recovered via fallback was written to a `.png`. Keep `recordFinished(rec, entry, fetchBody)` as an **injectable seam** so a test can simulate the failure — the earlier version's tests poked the maps directly and could not fail.
- **`fetchInPage` must refuse any URL `isGeneratedImageUrl` rejects**, before touching the page. It runs `fetch(..., {credentials:'include'})` in page context; without the guard it is an arbitrary-fetch-to-file-write primitive.
- Key by file id — one generated image arrives through several `<img>` tags.
- `files()` returns a copy, never the live map.

For `dimensions`, Go used `image.DecodeConfig`. In Node, parse the PNG/JPEG/WebP header directly (a small header read is enough for width/height) or take a lightweight approach — **do not** add an image-processing dependency for two integers, and make sure WebP is handled, since Go's version silently returned 0×0 for it.

- [ ] Port tests (including the injectable-seam ones) → fail → implement → green → mutation-check the eviction path → commit.

### Task 8: Composer driving and probe

**Files:**
- Create: `src/compose.js`, `src/probe.js`
- Test: `test/probe.test.js`

**Port source:** `internal/compose/compose.go`, `internal/probe/probe.go`.

**The embedded JS ports verbatim** — `SelectAllJS`, `collectJS`, `countMatchesJS` and the state-script template are already JavaScript inside Go string literals. Lift them out as real functions; they become `page.evaluate` callbacks. This is the single biggest saving in the port.

Carry over:
- `resolve(page, set, key, timeout)` tries candidates in order and throws a `SelectorMissError` carrying the key.
- **Clearing the composer must be contenteditable-aware.** `SelectAllText`-style DOM `.select()` throws on ChatGPT's contenteditable div — this broke every run and was caught only by the live smoke. Port `SelectAllJS`, which checks `typeof this.select === 'function'` first and falls back to Range/Selection. A failure to clear must NOT fail the run; log to stderr and continue.
- **Attachment upload waits for per-file removal controls and FAILS LOUDLY on timeout** — never proceed to send. A silent send without the attachment produces a plausible wrong image the user cannot distinguish from a bad generation. On deadline throw a `SelectorMissError` for `attachment_remove` so self-heal can reach it.
- `waitDone` polls `done(state, want)`; never a fixed sleep as a completion signal, never an early return on the first image.
- `archive` is standalone; the caller decides when. Never call it from `send` or `waitDone`.
- `probe.collect` emits `css` ONLY when genuinely selective (`#id` or `[data-testid=...]`), never a bare tag name — a bare tag patched to the front of a selector list makes `resolve` return an arbitrary element. Only `testid` and `css` are actionable; `role`/`name`/`text` are informational, and the dump says so in a `note` field.
- `probe.writeDump` sanitises `stage` — `../../etc/foo` escaped the target directory via path joining.

- [ ] Write probe tests (pure, browser-free) → implement both → green → commit.

### Task 9: The CLI

**Files:**
- Create: `src/cli.js`, `bin/gpt-imagegen.js`
- Test: `test/cli.test.js`

**Port source:** `cmd/gpt-imagegen/run.go` and `main.go`.

**Interfaces:**
- Produces: `run(argv, stdout, stderr)` returning an exit code; `safeRun(fn, stdout, stderr)`.

Commands: `setup`, `doctor`, `generate --prompt --out [--count N] [--ref FILE ...]`, `edit --image --prompt --out`, `probe --stage NAME`. Parse args without a dependency (`node:util parseArgs` is stdlib).

Carry over, all from review findings:
- **`run` must be a plain function taking streams** so tests drive it with buffers.
- **Salvage on timeout.** If `waitDone` times out but images arrived, save them and return `ok:true` with a stderr warning and **`archived:false`** — the turn is already spent and discarding real images is the worst outcome under a no-retry discipline. Leave the conversation unarchived as the recovery path. Only a timeout that salvaged nothing is a `TIMEOUT` failure, with `conversation_url` attached.
- **An uncaught throw must still produce exactly one JSON line** on stdout, with the error detail on stderr only and a generic stdout message. Make the wrapper injectable and test it with a function that throws; prove the test fails without the catch.
- A short set warns on stderr; the JSON schema does not change.
- `edit` with a missing `--image` must fail fast without launching Chrome.
- Fallback order for recovering image bytes: `recorder.url(id)` first, then a scan of `state.imageUrls`.

**Tests** (no Chrome, no login): unknown command → one JSON line, non-zero exit; missing required flags → one JSON line; missing `--image` → fast failure, no browser; stdout is exactly one line in every case (count newlines).
